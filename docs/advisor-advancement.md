# Advisor 持续 loop：可观测推进协议

核验日期：2026-10-01。推荐主指标为**固定总预算内，通过独立干预验证的任务成功率**。研究问题是：同一 AI 加动态 Advisor，是否比同预算的普通研究 loop 更常得到可执行、能预测新观测的提案。计分器已经实现，真实模型比较仍未测量；参考项目 [abduction-benchmark](https://github.com/ursinasanderink/abduction-benchmark) 当前只有预注册，不能声称已有可运行 worlds。

## 原始研究与优先入口

[Zahavy，ICML 2026 正式版《Position: LLMs can’t jump》](https://proceedings.mlr.press/v306/zahavy26a.html) 将从经验到新公理的生成视为瓶颈，主张交互世界模型提供 grounding。§5 明确将论文定位为未来实证测试的框架，而非决定性证明。我们检验可观测的研究行为，不用软件成功率判定所有 LLM 是否具有或缺少某种内在机制。

较新的 [Shi 等，arXiv v3，2026-09-12《When the Canonical Completion Is Wrong》](https://arxiv.org/html/2608.26187v3) 实测给定约束与答案空间内的默认结构替换；后续预测及跨阶段修订仍待实测。§§3.5、7 要求默认校准、正确解与匹配对照：默认答案出现得少，也可能只是答案错误或格式失败。其[官方 kan-jump-test](https://github.com/EEthanShi/kan-jump-test) 已发布机械评分与实例认证，可优先用作结构辅助验收；`python tests.py` 是无 API 的管线检查，不是 Advisor 科研收益实验。

主任务优先接入 [NewtonBench，最新核验 arXiv v3，2026-02-24 / ICLR 2026](https://arxiv.org/html/2510.07172v3) 的交互模拟环境，而非先虚构一套未发布的 worlds。[官方仓库](https://github.com/HKUST-KnowComp/NewtonBench) 提供环境与运行入口。论文 Appendix A.4 的 symbolic accuracy 使用 LLM judge，data fidelity 使用另留样本；本协议另增私有干预门，不能把原评分直接称为独立干预成功。原仓库 `modules/common/evaluation.py` 的 RMSLE 会过滤 NaN 并取绝对值，因此主判据还须检查全点有限、符号、域和完整覆盖。变更经典规律的模拟任务不保证现实物理可信，也不证明生成了开放世界的新理论（Appendix A.3.3）。

以上为三个论文及其两个官方实现的有界核验。优先路线是现有环境上的配对比较；私有干预门、成本适配与未改变规律的对照需先实现和冻结，本文不声称它们已经接入 RDS。

## 冻结比较对象与预算

实验前保存 manifest：环境与 evaluator commit/hash、任务清单、模型版本及 provider、采样设置、工具权限、起始证据、预算、容差、私有验收生成规则、控制任务、分析规则与停止阈值。公开 task 接口及合法操纵范围；隐藏 oracle 源码、答案、验收种子和具体点值。固定任务不得在看到结果后移除。

两组使用同一模型、证据、规则内容与工具。baseline 可以生成更多候选、主动探测、反思和修订；Advisor 组可以动态选择断口、补提案、重排及淘汰。比较改变的是调度与建议路径，不能给 baseline 额外限制以制造收益。人类只制定协议、整理输入和实现 oracle；不得在一组中暗中补入专家答案或强模型候选。每个候选保存生成来源；人类补题或模型版本变化使该轨迹退出既定比较并明确标记。

预算 `B` 覆盖完整轨迹：输入/输出及可计费推理 token、所有生成/Advisor/重试调用、环境探测、代码执行、检索及验证。先冻结成本单位和换算规则，同时记录原始资源向量；不能只比较调用次数或最后一次实验费用。两组得到相同预算机会与硬上限，实际消耗、残余预算和匹配误差另列；缺失成本保持未知，该次运行不能通过等预算结论。最终验收使用两组相同的固定验证配额，费用计入总账；没有强模型 judge 参与主评分。

## 每轮执行与独立验收

1. 从当前证据生成有类型提案，保存 `hypothesis_id`、新节点/关系、假设、变量身份、单位、作用域、可执行预测、竞争解释和干预计划。原图没有对应 rule ID 不自动拒绝新概念；表达不了的内容返回待定义，不能猜成已有概念。
2. parser、生成器和 evaluator 使用同一规范对象及 AST；保存对象 hash、变量映射和实际执行版本。干预收据核对实际被改变的变量、对照保持项与作用域，阻止“文字说改变 A，代码实际改变 B”。结构通过只表示可执行，经验支持仍待测。
3. 在研究通道执行允许的探测，把原始输出、失败、预算与正负结果下的下一行动送回 loop。提出新解释、选择实验、淘汰或修订均留轨迹；自填 `verified/SUPPORTED` 不关闭断口。
4. 在剩余预算内锁定最终对象，随后由隔离 evaluator 生成未用于拟合或选择的新操纵点。预先冻结误差函数、容差、点数、聚合规则、合法域及噪声处理；探测须覆盖能区分提案与现行竞争解释的变化。研究探测可反馈，最终验收点不能反复回传用于调参。
5. 成功要求干预有效、输出完整有限且在规定域内、预测满足冻结判据。失败或不确定分开保留；测试尚未执行不填零误差。随机环境需按预注册重复次数与不确定区间判断，证据不足保持未确认。

这里的“干预”首先指模拟环境中的受控输入操纵，不能自动提升为实验室因果证据。数学命题若宣称证明，须保存真实 Lean 内核收据并核对命题与执行对象一致；证明在假设下成立，不能认证这些经验假设。拟合、AST 合法或新节点出现，也不能替代以上验收。

## 五项观察指标

| 指标 | 可检查定义与用途 |
|---|---|
| **主指标 `R(B)` 与配对差 `ΔR(B)`** | `独立验收成功任务数 / 预先分配的目标任务数`；两组逐任务配对并报告不一致的胜/负数及预注册不确定区间。超预算、格式错误、超时、未完成均留分母，只有独立确认才计成功；未测状态仍是 `NOT_EVALUATED`，不冒称经验反证。 |
| **错误替换率 `F(B)`** | 在原模型已正确的控制任务中，被错误新模型替代的任务占比。语义等价改写不算错误替换；额外报告无需替换却发生替换的次数。需要未改变规律、同口径噪声和同预算控制，不能只有“必须跳跃”的题。 |
| 首次独立成功的成本 | 从开始至锁定并确认首个成功对象的累计成本；未成功轨迹保留为预算截尾，不能只对赢家平均。与总成功率、实际资源账并看。 |
| 生成池与排序/保留 | 保存过滤前全池及默认截断线。分别记录池内是否有随后验证成功的提案、共同池上能否保留它、默认线以下被救回且最终确认的数量。没有可枚举 oracle 时不声称完整召回率；救回不能归因于生成增益。 |
| 提案与执行一致性 | 记录新节点/关系、解析失败、对象/AST/执行映射不一致及未执行干预。新概念数是探索辅助量；只有通过独立验收的对象才提供推进证据，图规模本身不计成功。 |

`F(B)` 控制防止奖励盲目换理论；默认校准则防止把研究者指定的 canonical model 当成 AI 真正的默认。若校准显示 AI 原本就不选它，报告实际默认分布，不能将变化解释成“摆脱默认”。主指标先不使用 **mechanism recovered** 标签：数值预测成功不足以确认内部因果结构；只有结构匹配、可识别性及区分竞争结构的干预证据均核验后，才可报告对应范围的结构识别结果。

当前计分器将缺观测、缺预测或缺预算成本标为 `UNMEASURED`，完整队列的 `rate` 与配对差返回 `null`，同时给出固定分母下的上下界。不能把未测任务补零或删掉后声称整体收益。存在数值失败的任务即使还有未测点，也不能进入“可能成功”的上界。协议、单位、模型身份不匹配、确认数据用于选择或总预算越界返回 `INVALID`。CLI 的退出码 0 只表示报告已构造，需要继续读取报告状态。

预算按同一协议声明的资源向量分别累计，失败、超时及确认开销均保留；协议以外的成本另列未知，不自动换算或证明覆盖了全部真实成本。时间、哈希及来源仅有 `INPUT_REPORTED` 保证，外部执行器仍须认证来源、收据和独立性。`retention_control` 的数值失败率可以观察；真实错误替换率仍需独立的结构/等价类裁判，因此当前 `false_replacement` 和 `mechanism_truth` 保持 `UNMEASURED`。

## 已接入的程序与开发反馈

用 [计分器](../scripts/rds_advancement.py) 通过公开 CLI 读取冻结协议、两组轨迹和原始确认：

```bash
python -B scripts/rds_cli.py advancement score --protocol protocol.json --trajectories trajectories.json --confirmations confirmations.json
```

省略 `--confirmations` 可检查证据缺口，不能得到科研成功分。[可运行示例](../examples/advancement-loop/run.py) 在新空目录执行“未知成绩 → 数值确认 → Advisor 缺口与下一问题”：

```bash
python -B examples/advancement-loop/run.py --workspace <new-empty-workspace>
```

示例使用公开、脚本化算术及合成工作单位，只验收计分与反馈接口；零模型调用，样例成绩不是 Advisor 效用。看过的案例属于开发材料，不能继续作为独立收益测试。真实环境适配、模型通道隔离、执行对象与声明的一致性及独立干预门仍待接入。

针对防打转，另记录**重复否决提案次数、正负结果不会改变决定的实验数、未锁定计划的讨论数**。这些来自带来源、显式身份的决策摘要，不假装理解所有改写文本。首次有效决策的轮数与成本须由实际研究轨迹和事先冻结的有效性判据确认；锁定了一个计划不等于计划有效。防打转指标与独立干预成功率一起报告，不能通过少讨论但选错方向获得高分。

## 继续、停止与修改

- **继续既定批次**：语义链、成本与控制可审计，尚有预注册任务和预算。有限初批只报告可行性；收益不确定时按原计划收集余下任务，不能把一次成功当稳定增益。
- **支持进一步投入**：达到预先冻结的最小收益 `δ_min` 与错误替换上限 `η_max`，且配对不确定区间支持该判断；若控制退化，不能用更高的目标题成功率单独通过。阈值在看结果前由研究目标与投入确定。
- **停止当前运行**：预算/轮数上限、答案或私有验收泄漏、干预实现不符、成本不可核对。保存断点与所有失败；不得无限追加调用直到通过。
- **修改下一版协议**：池中没有合格提案则研究生成；已有合格提案被丢弃则研究选择；语义链或干预无效先修执行；多种结构在可用干预下等价则报告识别不足并寻找新观测。变更 manifest 版本后使用新任务，不改旧批次阈值或追认成绩。

最大失败风险是 benchmark 的人类设计者已经固定了变量、函数语言与验收世界，Advisor 只更善于搜索这个空间。防泄漏和新措辞不能消除这一边界。配对结果最多支持“该环境、预算和模型下的独立验证推进改善”；历史切片命中、给定约束的结构通过与模拟规律恢复均不能单独证明未知科学发现，或解决论文所讨论的全部溯因问题。
