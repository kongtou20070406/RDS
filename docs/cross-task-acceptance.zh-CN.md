# RDS 5.8 跨任务验收标准

[English](cross-task-acceptance.md) · [5.8 愿景](5.8-vision.zh-CN.md) · [文档目录](README.zh-CN.md) · [Issue #22](https://github.com/kongtou20070406/research-direction-selector/issues/22)

RDS 是一个通用科研方向选择器。本文细化现有的 [V1–V6 计划](5.8-vision.zh-CN.md#重点工作包与验收标准)
与 [issue #22](https://github.com/kongtou20070406/research-direction-selector/issues/22)。
这是一份实施与审查计划，不声明下述检查已被全面强制执行。初始交付优先级为深度学习、软件与工具开发，
其次是数学。它们提供第一阶段的验收覆盖，而不是将产品边界限定在这三个领域。其他领域可以在提供适用可选适配器
和声明验收谓词的前提下使用同一套内核。

这一全库级边界同样适用于可选工具与示例：不得发布特定于单一项目的解决方案、配方或策略。
保留可复用的参数化方法与极小化公开/合成失败用例。现存特定于具体项目的可执行内容应从已发布的工具路径中移除，
或由此类可复现用例替换；原始实证证据应保留在私有归档中。

## 初始场景联合检验的内容

| 共有需求 | 深度学习示例 | 软件/工具示例 | 数学示例 |
| --- | --- | --- | --- |
| 原始目标推进 | 训练正常运行但要求的质量曲线仍未达标。 | 测试通过但对外宣称的 CLI 永远无法送达消费者。 | 覆盖上界仍使全局最优性处于未决状态。 |
| 适用性检查 | 处于未激活状态的损失函数具有有限零导数；连通性需要受控探针。 | 缺失可选后端不同于畸形输入或软件故障。 | 无法得出确定结论的区间盒属于未决，而非反例。 |
| 有效迁移 | 不同的评测输入尺寸需要校验已声明的几何结构与指标协议。 | 更快的计算内核必须保留调用方、证人与恢复语义。 | 问题规模变更需要重新实例化定理的前提条件。 |
| 有益的下一步决策 | 对比具有不同预测后果的干预措施，保留失败配方。 | 在增加下一层抽象之前，先修复已暴露的边界问题。 | 定位缺失的归约或更强的界限，而不是重命名未决分支。 |
| 恢复与成本 | 在中断后对账原始远程发起任务与已提交的检查点。 | 已计费的中断尝试不得触发重复发起或退款。 | 保留未决的前沿状态与已消耗的搜索配额。 |
| 证据适度性 | 在不重新运行完整训练的情况下复用未变更的指标/标定证据。 | 复用逐操作图/哈希计算，并度量完整入口延迟。 | 复用界限证书而不重新打印整个证明树。 |

上述示例描述的是失败模式，而非将每一项历史失败归咎于 RDS。请首先核对原始证据与精确安装的软件修订版本。
例如，源码清单标识与手动成本合并已在 #30 和 #11 中得到修复。特定于项目的检查器或 GPU 脚本需要其专属可复现用例；
通过 RDS 上报的错误并不自动构成 RDS 的实现缺陷。

## 实施顺序与可观测验收

### 1. 重复控制与所有权归属 — V2/V4

在现有的 SQLite 事务中完成冻结的 opt-in 执行策略。
测试计费前拒绝重复注册、并发调用方、重命名的请求、变更的绑定输入、成功结果复用、损坏的收据、
计费后缺失子任务以及陈旧/复制的子任务标识。有效的新对比或经授权的复现必须在契约中拥有显式路径。
精确的标识匹配并不能在任意算法之间确立语义等价性。

### 2. 门禁证据与实用诊断 — V1/V3/V5

在现有的协议、事实与收据字段中，将操作有效性、科学资格、容量与最终目标验收严格区分。
每个配置的门禁都需要具备来源、适用领域、证据以及消费者。
一次失败必须指明实际字段或检查项、预期条件、观测值以及相关工件。缺失的测量数据保持未知（unknown）。

对于神经网络适配器，使用小型受控输入测试存活但未激活、断开连接、数值抵消、非有限值以及形状不匹配等情形。
仅凭零梯度既不能证明接线正确，也不能证明连接断开；局部的响应增益单凭自身无法确立最终质量。
对于理论适配器，包含在既定前提下的未决、已被证伪与已验证的义务。
对于开发者适配器，包含无效输入、依赖不可用以及实际实现错误。

保持资源授权的硬约束。将管理性不匹配与数学或经验判决分开记录；调查其溯源，
而不是将失败篡改为成功。当实现的或应用的前提未经核验时，条件定理仍保持条件性。

### 3. 改变选路决策的结果 — V1/V2/V3

消费项目声明的结果向量、单位、方向、不确定性、对比标识以及验收谓词。
这可以描述质量对比推理开销、证明义务对比剩余定义域，或是正确性对比延迟/上下文成本。
不得强制规定 PSNR、固定步长网格、通用单调性阈值或单一综合评分。

测试应能够区分主要指标改善但受保护条件失败、平台期、不兼容对比以及缺失测量。
Advisor 必须在下一步动作中保留这些区分。停滞的路线应指明未决的假设与具有差异的预测或证明义务，
然后将提议的检查与最小修复方案进行对比。不得自动调整损失权重、强推某种架构或消耗额外的实验配额。

### 4. 迁移与续行 — V3/V4/V5

对领域参数、张量形状、后端/解释器与资源限制使用显式的适配器输入。在昂贵的分发执行前进行校验。
兼容的动态形状不因先前输入具有不同分块计数而判定为失败；变更的科学评测协议仍需要新的绑定。

扩展现有的运行器/适配器所有权，而不是创建第二个常驻守护进程。
测试陈旧进程 ID、中断的传输、存活的归属作业、已完成但收集失败的作业，以及具有部分后续写入的原子性已提交检查点。
将不受支持的远程对账报告为未决，不得重复发起，也不得虚假声明进程已停止。
仅在绑定的策略下停止已识别的归属作业。预估费用、预留额度、墙钟时间与度量的设备时间保持区分；缺失的测量不等于零。

### 5. 性能与反馈 — V5/V6

在进一步加速之前，对完整的用户入口进行性能剖析：冷启动 CLI、源码读取/哈希复用、图/阻断割分析、
候选审查、序列化以及必要的验证。保留原始对齐检查与匹配的前后对比样本。
#32 中的 Python 优化是新的对比基线；原生加速必须在匹配的输入上计入加载、类型转换与调用方开销。

采用简明输出，仅加载与决策相关的记录。#33 中的私有交接工作流应保留最小可复现失败、原始决策、
绑定版本与遗漏项。紧凑的历史摘要不是完整的重放数据包。已读取的示例是开发证据，而非未经触碰的确认。

## 交付边界

每个实现的 PR 都应指明其修复的共享机制，并测试来自三列的适用情形，包括条件变更情形。
使用公开或清晰标记的合成固件；避免将私有归档与机器标识带入代码仓库。
任何固定的轮数都不能证明某种科研方法必然无效，通用的剪枝定理或任意代数恢复保证也均不属于此类软件变更的范畴。
科学算法的改进需要其专属的作用域证据与独立审查。
