# 从受阻路线到可检验的新方案

[English](evidence-grounded-jump.md) · [5.8 愿景](5.8-vision.zh-CN.md) · [跨任务验收](cross-task-acceptance.md)

**实现契约提案，2026-10-02；基线 `c4506ed`。** 本设计细化 [issue #22](https://github.com/kongtou20070406/research-direction-selector/issues/22) 的 V1–V6，不增加运行时门禁。下文区分现有行为与待实现消费者。

RDS 是**通用研究方向选择器**。这里的目标是帮助智能体提出并检验真正改变下一步的路线，证据检查和超图为此服务。首批验收顺序为深度学习、软件工具开发、数学，这些是验收场景，不是适用边界。复用参数化方法和显式适配器，不向 RDS 或可选工具包导入特定项目解法、训练配方或固定科研阈值。

## Jump 必须落到研究动作

保留原始目标和验收标准。候选可改变模型假设、表征、干预或计算方法，要说明它与最小合理修补有何不同后果，以及如何通过允许的检查区分二者。候选在准许研究前不必已经得到证明或提升最终指标；改变计算方法也不一定是改变公理。

```mermaid
flowchart LR
    E["观测、开放义务或有价值的反事实问题"] --> A["定位可修改假设或计算障碍"]
    A --> J["提出不同路线，与最小修补比较"]
    J --> P["不同预测或证明义务"]
    P --> X["绑定适用且已授权的检查"]
    X --> U["评估证据，修订受影响依赖"]
    U --> N["执行有依据的下一步"]
    U --> A
```

模型或研究者提出语义变化，计算图闭包不会自动发明解释。Advisor 必须通过现有 `selection_review.next_move`、候选 action、checkpoint 和 runner 消费提案及检查结果。复用[理论改写流程](theory-reformulation.md)，不建立第二套 jump 账本或自主改题器。

下一步决策的消费者必须：

1. 指出原目标尚未闭合的义务，分开研究者约束与智能体自行引入的假设。缺测、实现错误、冲突观测和已核验反例应触发不同响应。
2. 需要重表述时，提出具体替代路线并与最小可行修补比较。明确改了什么假设、表征、干预或方法，以及同作用域内哪项预测或证明义务会不同。只检索适用工具摘要；改名、加节点或多一张收据不够。
3. 将判别检查绑定到真实输入、选定且可用的适配器、不同结果对应的后续决定和现有预算。缺少适配器或可区分观测时，明确相应开发／测量义务，不编造命令或成功结果。
4. 执行已授权检查，根据实际结果继续、收窄、修补或替换路线。保留负结果和未解决状态。模拟只支持其编码假设下的结果，迁移到目标系统仍是显式义务。

重表述不必等到反复失败，研究者要求探索不同表示时也可启动。不强迫健康的单条证明义务编造竞争对手，不要求每个常规步骤都 jump，也不在固定次数失败后强推更高级理论。实质改变用户目标、方法限制或投入仍须用户决定。

| 首批场景 | 实质提案 | 判别检查及可能的后续动作 |
| --- | --- | --- |
| 深度学习 | 比较更新规则修补与状态表示变化，说明不同轨迹预测。 | 在真实实现上按声明的匹配条件做受控探针，据测量选择已具备条件的实验；玩具稳定性不能认证任务质量。 |
| 软件工具开发 | 提议原生重写前，区分重复依赖分析与算法本身开销。 | 测同一完整 CLI 工作负载及身份／恢复行为。复用分析已足够就采用复用；原生方案需由实测取舍支撑。 |
| 数学 | 比较局部引理修补与同一命题的有限归约或替代表述。 | 检查归约、定义域覆盖和证书义务。反例可否决对应作用域命题，有限检查成功不能闭合无界命题。 |

## 当前超图实际建立了什么

[分析器](../scripts/rds_hypergraph.py)报告 `INPUT_REPORTED_DEPENDENCY_ANALYSIS_NOT_PROOF`。[Advisor 消费者](../scripts/rds_advisor_search.py)和[目标绑定入口](agent-entry.md#goal-linked-dependencies)使用声明图，不是任意科研断言的验证器。

| 已核对的基线行为 | 下一步所需消费者 |
| --- | --- |
| 手写 `SUPPORTED` 节点／规则进入 `declared_supported_closure`，来源 locator 即可作为合法输入。 | 保留声明，从适用已检查证据与显式假设构造准入支持，不能静默升级声明。 |
| `--audit-files` 单独报告字节身份；`MISMATCH` 不改变声明闭包。 | 在提升结论、复用或依赖它派发前拒绝失配绑定，指出受影响义务及修补／检查动作。 |
| 对变化后的图重算，可撤去支持并保留独立 OR 路径。[原生反驳记录](native-research.md)把受影响依赖标为需复审。 | 将已核查证据变化接到图和后续消费者，保留替代路径与原记录；自动证据驱动修订尚未交付。 |
| `declared_derivation_rules` 保存按输入扫描顺序出现的首条推导。 | 支持变化时考虑全部适用替代路线；首个见证既不是唯一证明，也不是因果诊断。 |
| 有界阻断集枚举报出截断及不完整集合。 | 选路／准入保留不完整性，不把截断说成不可能性或穷尽的替代路线列表。 |

极小缺失证据集是在输入图上按包含关系极小，不一定数量最少、成本最低或科学上充分，可以有多个。按目标关系、判别价值和可比较成本推荐少量动作，在完整记录中保留替代路线。不删除目标外资产，也不要求所有重表述落在某个选定集合上：补上有依据的缺失桥梁可能改变图本身。

在已核对基线上，通过 `rds_cli.py hypergraph --audit-files --json` 跑四个合成输入，确认：来源失配仍输出 `DECLARED_SUPPORTED`；撤去唯一前提会移除后果；独立 OR 路线保留后果；组合上限为一时退出码为 2，返回 `UNKNOWN` 和不完整阻断集。这些是入口行为观测，不能证明所有图算法或科研输入都正确。

## 绑定证据，同时允许形成新假设

**没有适用的已检查证据，不得提升为已验证结论，也不得作为已成立前提依赖。** 未知／候选节点、显式假设、文献引用和新想法仍能表达，必须保留已授权的开放命题调查。纯数学不必出示 GPU 收据，所有科研声明也不都需要 Lean。

复用已有目标／claim 身份、scope、定义域／参数、来源哈希、run／receipt 身份、adapter／backend、`status`、`assurance` 及产物定位符。适配器契约必须标明实际检查命题与目标声明的对应关系。复用现有 ledger/CAS 所有权，不增加平行证据数据库，也不静默改变旧图 schema。

- 哈希绑定字节，不提供加密、外部签发者真实性或科学真理；字节相同和退出码 0 不能单独提升支持。
- 形式支持需要针对真实编码命题和允许前提的适用检查结果，保留实际公理与原问题对应关系。精确有理证书可能就是适用契约，Lean 不能弥补原目标编码错误。
- 经验支持需要声明的运行／数据／评价身份、测量及相关对照／不确定性。抽样收缩不是普遍稳定性，阈值不是通用因果定理。
- 文献或人工前提可支持明确标注来源的条件路线，不能伪装成本地执行或补齐缺失应用前提。
- 导入文本、JSON 成功标签和包内脚本不能选择可信验证器、注册规则或授权执行。适配器代码与验收标准须独立于被检查数据进行审查。

提升结论、复用证据和执行时重查相关绑定及当前目标，来源变化前的建议已过时。假设图分析仍可用但须明确标注；严格证据消费是一项显式工作流能力，不能从使用旧分析器推断已启用。

## 反例与依赖修订

核验过、绑定作用域的见证只修订它实际反驳的命题。运行失败、超时、未激活梯度或总指标变差都不自动构成反例。下游失败只给出可能出错的假设、实现或迁移条件；没有判别检查就不能认定责任前提。

相关证据不可用、冲突或被证伪时：

1. 通过现有记录追加证据／修订，保留原产物、成本、暴露和原因。不将所有下游声明覆盖成 `CONTRADICTED`，也不删除证据。
2. 从当前有效基础证据和规则／应用绑定重建准入支持，不把昨天的派生闭包作为今天的可信种子；无基础支持的环不能自证。
3. 重评受影响 AND/OR 依赖。必要 AND 前提失效使该推导暂停，独立有效 OR 支持或直接证书可保留结论。冲突证据保持可见，不能由最后一次写入决定真相。
4. 拒绝**依赖**失效支持的新任务，同时允许适当绑定的调查、见证检查或修补。重开须有证据／scope 变化或绑定修复及原因，改路线名不算。
5. 重算原目标未闭合义务并用于下一选择。停止正在运行的工作仍通过现有进程所有权和已授权停止策略，保留部分结果及已花预算。

先对当前快照做一次有界重算，复用近期每次操作只分析一次的优化。没有同负载完整入口测量支撑前，不增加持久化增量真值维护服务。以后若实现增量算法，撤销、替代路径、循环和中断更新必须与重算一致。

## 程序后果与简短反馈

| 条件 | 消费边界必须执行的后果 |
| --- | --- |
| 自报成功、claim／scope 不符、来源变化或必要证据不可用 | 预留／启动前拒绝结论提升或依赖，返回具体缺失绑定和合法补证据／修补动作。 |
| 适用的已核验反例 | 阻断对被反驳作用域命题的原样依赖，将见证及被检验假设用于替代路线生成，不自动指定某个理论。 |
| 目标／方法不符或配置额度耗尽 | 强制执行已有拒绝／停止策略，模型口头确认不能覆盖。 |
| 图搜索未完、后端不可用或来源冲突 | 保持未解决，拒绝依赖完整性的决定；允许已授权有界诊断或有依据的重表述，不制造科学判决。 |
| 输入相同且有兼容的已完成检查 | 复用结果；等价标签、摘要和重复 PASS 不增加目标进展，配置重复策略控制派发。 |

预期信息增益是研究假设，不是普遍可计算门禁。不能要求测出柯尔莫哥洛夫复杂度或保证收益，才允许不确定实验。检查声明的判别后果，如实记录不确定／负结果。每个拒绝都必须指出真实绑定／策略原因及合法下一步。

上下文只返回当前原目标义务、一个下一动作、判别观测／结果及已有证据定位符。完整替代路线和证据留盘，只在实质变化时汇报，不每调用刷卡。普通展示不扫全项目；每次操作对每个相关唯一文件至多读取／哈希一次，到下一个真实信任边界再核对。分别测完整入口延迟、字节和读取次数，不假设字节等于 token。

## 聚焦实现与验收

沿用[贡献规范](../CONTRIBUTING.zh-CN.md)及 V1–V6 所有权，每个 PR 实现一个消费者，提供真实 CLI 复现与正、负、边界、恢复案例。合并本文不会发布新版。

| 步骤／现有职责 | 必须交付的行为证据 |
| --- | --- |
| **1. 证据接入支持 — V1/V4** | 自报支持、claim／scope 不符、字节匹配但未检查、建议后来源变化不能准入依赖。适用有效证据和已授权补证据动作均可用。断言真实派发及预算后果。 |
| **2. 修订依赖 — V1/V5** | 撤去唯一 AND 支持，保留独立 OR 支持，拒绝自证环及过期派生种子，保留冲突观测与收据。中断后恢复单一一致状态，不退还已花预算或重复派发。 |
| **3. 消费 Jump — V2/V3/V6** | 记录的失败／开放义务促成与最小修补不同的可执行预测／检查，真实结果改变下一动作。改名／等价检查不计进展。覆盖健康路线、无后端，以及旧阻断集之外的有效新桥梁。 |
| **4. 验收可复用改进 — V3/V6 与 RSI** | 使用[回收提示词](research-record-handoff.md)和[RSI 流程](rsi-evolution.md)，由 [#33](https://github.com/kongtou20070406/research-direction-selector/issues/33)追踪。采用前审查预期行为和最小复现，归档包不能自行执行／采用规则。保留回滚，复用失败仍是开发案例。 |

在深度学习、软件和数学夹具中验收，不携带特定项目解法。覆盖有界截断、缺证据、未经授权路径越界及后端失败。与同一基线比较最终入口延迟、输出和文件读取，实测更强检查的额外成本。这些测试证明软件行为，不代表普遍科研突破率；修复消费者不需要先启动新外部 benchmark。

## 研究启发

[Zahavy 的 ICML 2026 立场论文](https://proceedings.mlr.press/v306/zahavy26a.html)尤其第 4 节，启发我们区分假设形成与演绎，并提供可操控干预。2026-10-02 核对的[作者范围澄清](https://www.tomzahavy.com/projects/llms-cant-jump)明确未否认 LLM 系统能进行科学发现。这启发上述有界工程循环，不是不可能性定理、RDS 性能结果、通用世界模型的必备要求或永不失误的承诺。
