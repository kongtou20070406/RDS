# RDS 未来计划

RDS 的目标是自动化辅助人类持续推进科研。固定五个组件：Skill、执行与验收内核、研究状态与记忆、Advisor、RSI。六个科研环节是工作流程，L3/L4 是能力层级，Lean4 与 Obelisk 是适用子任务中的协作能力。

## 近期：让建议可以复核

优先完成 Advisor 的证据闭环：从有来源的事实检查规则条件，沿判断依赖组合候选，展示竞争解释、所需观测、结果如何改变下一决定及增量成本。缺事实输出明确查询，缺成本保留未知，不制造成功概率。未经审查的文档摘录继续保留 `UNREVIEWED` 身份。

验收依据是公开任务改编挑战、已有失败案例与有独立保留部分的回归集。检查缺证据时能否保持未知、错误机制归因能否被阻止、约束改变是否会改变建议，以及人能否从来源复核建议。组件测试通过不等于端到端科研效果已经提高。

## 下一步：接入真实科研记录

为一个真实研究项目接入现有训练器的配置、曲线、有效算子、数据暴露与完成收据。先读取已有产物，再把确实影响下一决定的未知项变成有界探针。复用关键代码、seed、数据与协议兼容的完成对照；没有已观测 seed 不稳定性时，不增加多 seed 任务。

验收要求建议能指向原始记录，执行结果能回到同一问题与计划，任务收益和机制证据仍分开判断。真实 GPU 训练适配尚不能由标量参考执行器或 UI 展示代替。

## 后续：评估研究建议与规则改进

以真实研究轨迹比较 Advisor 对下一决策的帮助，包括错误方向被及时排除、有效候选被保留、证据获取成本和人工修订负担。先明确研究问题与总预算，再决定是否值得运行完整的公开科研基准。避免把同一批已知案例反复修到通过后称作泛化验证。

RSI 提出的规则修改进入隔离候选集：记录依据、适用范围、反例和版本，在未用于提出修改的案例上评估，达到预先设定的采用条件后再升级；保留回退路径。测试不能保证所有未来场景不退化。

## 数学协作与界面

沿科研需求扩展已有 Lean4 原生义务与 Python 领域证书的适用范围，优先复用 Lean4/mathlib 能力。每项证明都保留精确声明与定义域，证明结果不自动升级为训练成功或机制成立。通用深度学习模型翻译仍是待验证工作。

只读工作台优先帮助真人查看当前问题、证据、预算和下一决定。执行、写回或后台任务能力另行通过真实适配与验收后提供，不在界面提前表现为已实现。

这些是按证据推进的顺序，不是日期承诺；投入明显改变时由研究者决定。
