# Research Direction Selector 术语表

[English](terminology.md) · **简体中文**

本表统一 RDS 五个组件和文档使用的术语。RDS 自动化辅助人类科研，研究者确定目标与资源。中文译名用于解释概念，不改变代码字段或取值。命令、数据格式、示例与执行记录中的 `task_gain`、`run_status`、`status`、`assurance` 等标识保持原样。

## 组件术语

科研规程 Skill、执行与验收内核、研究状态与记忆是三个基础组件；Advisor 与 RSI 是两个增强组件。这些是软件职责，采用的 L0–L5 等级描述跨组件的科学发现自动化程度。

| 组件 | 英文 | 在 RDS 中的含义 |
| --- | --- | --- |
| 科研规程 Skill | Research protocol Skill | 围绕意图、证据、实验设计、结果和任务接续的协作规程。规程中的指令与程序强制执行的行为不同。 |
| 执行与验收内核 | Execution and acceptance kernel | 所支持的计划、约束、执行、验证、产物、收据与恢复机制。适用的数学检查是该职责下的一项能力。 |
| 研究状态与记忆 | Research state and memory | 用于保留科研证据与决策依据的 `.rds` 项目记录、判断图与 Obelisk 历史检索；运行记录与历史来源承担不同角色。 |
| Advisor | Advisor | 沿真实证据、判断依赖和有范围的规则生成或组合候选，使实验能够区分竞争解释、改变下一次决策，再筛选费用成本。 |
| RSI | RSI | 提出、评估、采用或回滚有范围的规则与工作策略变更；不表示模型智力自动提升。 |

当前 Advisor 辅助程序提供诊断线索、有范围的规则检索，以及基于来源标签事实、显式候选绑定与前置依赖的有界图搜索，保留未知条件和不同结果对应的下一步决定。一般性的研究想法自动发现与组合仍是发展方向，组件基准也不测量独立科学成功率。规则匹配只是线索，适用性仍需证据。RSI 的策略改善需要在相同总预算下独立比较完整研究轨迹。Lean 兼容工作适用于合适的数学子任务，不为更广的科学结论提供认证。

## 研究与实验术语

| 英文／代码标识 | 中文 | 在 RDS 中的含义 |
| --- | --- | --- |
| claim | 研究声明 | 待检验的研究表述，包含范围、量词和必需机制。研究声明可能比单个形式化后端检查的形式命题更广。 |
| proposition | 形式命题 | 在声明的假设和定义域下交给验证器检查的数学命题。其成立不自动证明更广的研究声明。 |
| property | 性质 | 实验要检验的具体条件或行为。只有参数变化实际改变了所声明的性质，才能用来检验该性质。 |
| judgment | 判断 | 依据证据作出的研究决策。判断规则有适用条件和证伪条件，不是普遍性能定律。 |
| assessment | 证据评估结论 | 根据结果记录的解释，例如任务收益或机制的评估结论。评估结论与其读取的执行记录不同。 |
| `task_gain` | 任务收益 | 在声明的比较协议下，主指标的改善。指标收益本身不证明机制证据。 |
| mechanism | 机制证据 | 关于待检验解释或性质的证据。执行成功或跨过阈值本身不证明因果支持。 |
| exposure | 数据暴露 | 已记录的数据访问或使用，包括查看、训练和选择。这里关注后续确认的独立性，不只指隐私泄露。 |
| control | 对照 | 作为比较参考的实验组或计算。与干预相关的条件应保持匹配。 |
| treatment | 干预 | 应用所提变更的实验组或计算。实际执行的变化必须对应所声明的干预。 |
| confirmation | 独立确认 | 冻结选择后，按照预先声明的协议，在未影响该选择的数据上进行评估。反复复用的测试集不能提供独立确认。 |
| policy improvement | 研究决策策略改进 | 选择研究行动的过程得到改善。需要在相同总预算下比较完整研究轨迹；单次模型结果成功并不足够。 |

## 验证与执行术语

| 英文／代码标识 | 中文 | 在 RDS 中的含义 |
| --- | --- | --- |
| admission | 准入 | 判断计划当前是否满足执行前的相关条件。准入不代表其科学声明已获支持。 |
| gate | 门禁 | 检查必须满足的约束，例如预算、数据使用或已声明的形式化义务。门禁不是操作系统安全边界。 |
| `status` | 检查状态 | 检查报告的结果，例如 `PASS`、`FAIL` 或 `UNKNOWN`。应结合产生该字段的记录理解。 |
| `assurance` | 验证依据类型 | 验证器所检查依据的类别描述。它不是置信度分数，也不是研究质量排名。 |
| certificate | 证书 | 提交给相应后端检查的证据产物。其格式、适用范围和接受条件由形式化验证指南定义。 |
| receipt | 执行收据 | 引擎生成的执行记录，包含绑定信息、执行状态、结果和产物引用。收据本身不证明科学解释。 |
| recovery | 恢复 | 工作中断后，恢复或核对执行状态与记录。恢复本身不授权新运行；是否重跑由执行协议决定。 |

`run_status` 表示执行状态，与验证器的 `status` 分开。类似地，执行收据记录执行事实，证据评估结论解释结果。翻译日志或说明运行时，应保留这些区别。

## 检查状态与验证依据类型

`status` 和 `assurance` 回答不同的问题：**检查的结果是什么，以及检查了哪种依据？** 两个字段都不是等级分数。尤其不能把 `PASS` 等同于任务收益已确认或机制证据已获支持。

| `assurance` 取值 | 所属范围 | 含义 |
| --- | --- | --- |
| `AST_ONLY` | 主干 | 普通参考路径中的 AST 检查，不是形式化证明证书。 |
| `SYMBOLIC_CHECKED` | 主干 | 在声明的适配器范围内完成符号检查，不自动等于经过独立检查的证书。 |
| `NONE` | 主干 | 该检查未声明验证依据。 |
| `CERTIFICATE_CHECKED` | 主干，由 PR #2 引入 | 已在支持该类型的后端所声明的范围内检查证书。 |
| `LEAN_KERNEL_CHECKED` | 主干，需配置原生 Lean | 原生 Lean 独立检查固定模板的闭合有理数关系，公理审计为空；不覆盖更广模型声明。 |
| `EXACT_OBSERVATION_CHECKED` | 主干，由 PR #2 引入 | 已在支持该类型的后端所声明的范围内检查精确观测。 |
| `EXACT_COUNTEREXAMPLE_CHECKED` | 适配器内部证据 | 已检查精确前向反例；通用框架外层结论使用 `CERTIFICATE_CHECKED`，须核对结果字段与版本。 |

这些取值是类别，不是有序阶梯，也不代表所有版本都支持。应结合检查状态、声明的形式命题、定义域和后端范围理解。各后端的精确支持范围与接受条件，以[形式化验证指南](formal-verification.zh-CN.md)为准，并区分历史基础版本、当前主干与后续适配器。

## 采用的自主等级与历史标识

RDS 采用 Kramer 等（2026）的 L0–L5 六级科学发现自动化框架，保留编号与含义。L1–L4 分别涉及科研辅助、重要环节自动化、限定领域的完整发现循环、跨领域循环及有限自主设置目标。[自主程度说明](research-autonomy.md)列出原名和来源。

这些等级不是组件列表、SQLite 状态机、科研质量评分或安全认证。现有 L3 参考运行器命名与原先 L4 策略改进标签是历史工程标识，不能据此声明达到对应的外部自主等级。保留代码与 CLI 标识兼容，面向用户称为受限参考运行器或 RSI。

| 术语 | 在 RDS 中的含义 |
| --- | --- |
| 执行契约 | 所支持工作获得授权的行动、数据、评估器、环境、资源与证据约束。 |
| 停止与恢复条件 | 对失败或失效工作的操作响应，包括保存产物、核对资源以及记录恢复条件；不是自主等级定义。 |
| RSI | 提出和评估策略变更的独立组件。在未使用独立案例上按相同总预算前瞻验证收益，与自主程度分开。 |

实际实验循环涉及契约、假说、门禁、执行、收据、评估和下一决定。任务收益、机制证据和执行状态保持分开，`PASS` 或一次评估不能建立自主等级；当前能力见[研究工作流](research-workflow.zh-CN.md)。
